### 🔴 ทุกคนวัดผลบนชุด A ถึง D เท่านั้น

ตัวเลขในรายงานของทั้งสามคน (`hash_table.py` · `search.py` · `sort_group.py`)
**ต้องมาจากชุด A, B, C, D ครบทั้งสี่ชุด** จาก `make_dataset()` ตัวเดียวกัน
ไม่ต้องมีชุดเสริมของใครอีก เพราะชุด D ใหญ่พอแล้ว

เหตุผล: รายงานสามหัวข้อจะเทียบกันได้เฉพาะเมื่อวัดบนข้อมูลชุดเดียวกัน
ถ้าแต่ละคนวัดบนข้อมูลของตัวเอง ตัวเลขจะอ่านเทียบกันไม่ได้เลย
และกรรมการจะเห็นทันทีว่าสามหัวข้อไม่ได้คุยกัน

### ทำไมชุด D ถึงเป็น 1,000 รายการ (เปลี่ยนจาก 120)

ที่ 120 รายการ ความต่างยังไม่ชัดพอจะสรุปอะไรได้ วัดจริงจาก `hash_table.py`
ตารางแฮชเร็วกว่าการวนหาใน list แค่ **1.4 เท่า** ซึ่งอยู่ในระดับที่ความคลาดเคลื่อน
ของเครื่องกลบได้ พอขยับเป็น 1,000 รายการ กลายเป็นเร็วกว่า **11 เท่า**
ซึ่งชัดพอจะขึ้นกราฟและอธิบายได้ว่า O(n) กับ O(1) ต่างกันอย่างไร

ที่ไม่ไปไกลกว่า 1,000 เพราะ bubble sort ของ Kul เป็น O(n²) และต้องรันสดได้
ตอนอัดวิดีโอ — วัดจริงบนเครื่องของ Kim ได้ประมาณนี้

| จำนวนรายการ | เวลา bubble sort |
|---|---|
| 120 | 0.001 วินาที |
| **1,000** | **0.07 วินาที** |
| 2,000 | 0.29 วินาที |
| 4,000 | 1.42 วินาที |

1,000 รายการจึงเป็นจุดที่ได้ทั้งสองอย่าง: ความต่างชัดพอจะสรุป
และยังรันสดหน้ากล้องได้โดยไม่ต้องนั่งรอ

`hash_table.py` มีรอบวัดที่ 4,000 รายการอยู่แล้ว เก็บไว้ได้ในฐานะ**ข้อมูลประกอบ**
แต่ตัวเลขหลักที่ใส่ในรายงานให้ใช้จากชุด A ถึง D

**สถานะตอนนี้:** `datasets.py` ยังไม่เสร็จ (งานของ Neo) `hash_table.py`
จึงวัดบนข้อมูลตัวอย่างของตัวเองไปก่อน และมี TODO กำกับไว้ท้ายไฟล์แล้วว่า
ต้องกลับมาเพิ่มรอบวัดผลบนชุด A-D — ใครเขียนอัลกอริทึมเสร็จก่อน `datasets.py`
ให้ทำแบบเดียวกัน คือใส่ TODO ไว้ท้ายไฟล์ อย่าปล่อยให้ลืม

**ข้อควรระวังเวลาเอา `make_dataset()` มาใช้:** ห้าม `import datasets`
ในไฟล์อัลกอริทึม เพราะผิดกฎ stdlib เท่านั้นด้านบน วิธีที่ถูกคือ
ใน Colab วางเซลล์ของ `datasets.py` ไว้ก่อน แล้วส่ง list ที่ได้เข้าฟังก์ชัน
วัดผลตรงๆ ส่วนในโปรเจกต์ให้เขียนสคริปต์วัดผลแยกไว้ข้างนอกโฟลเดอร์ `algorithms/`
