# การนำระบบขึ้นใช้งานจริง (Deployment)

| ส่วน | ที่อยู่ | ทำไม |
|---|---|---|
| Frontend (Next.js) | **Vercel** | เจ้าของ Next.js เอง ต่อ GitHub แล้ว deploy ให้อัตโนมัติทุก push |
| Backend (FastAPI) | **Railway** | รัน Dockerfile ที่มีอยู่แล้วได้ตรงๆ |
| ฐานข้อมูล (PostgreSQL) | **Railway** | อยู่โปรเจกต์เดียวกับ backend คุยกันผ่านเครือข่ายภายใน ไม่ออกอินเทอร์เน็ต |

**ลำดับสำคัญ: ขึ้น Railway ให้เสร็จก่อน** เพราะต้องเอา URL ของ backend ไปตั้งที่ Vercel

> 🔴 ห้ามเขียนค่าจริงของ `JWT_SECRET` รหัสฐานข้อมูล หรือ token ใดๆ
> ลงไฟล์ใน repo ทุกกรณี ค่าเหล่านี้กรอกในหน้าเว็บของ Vercel และ Railway เท่านั้น

---

## ขั้นที่ 1 — ฐานข้อมูลบน Railway

1. สร้างโปรเจกต์ใหม่ที่ [railway.app](https://railway.app) → **New Project**
2. **+ New → Database → Add PostgreSQL**
3. เปิดบริการ Postgres ที่เพิ่งสร้าง → แท็บ **Variables** จะเห็น `DATABASE_URL`
   หน้าตาแบบนี้ (ตัวอย่าง ไม่ใช่ค่าจริง)

   ```
   postgresql://postgres:xxxxxxxx@postgres.railway.internal:5432/railway
   ```

ยังไม่ต้องก๊อปไปไหน ขั้นต่อไปอ้างถึงค่านี้ด้วยการอ้างอิงตัวแปร ไม่ใช่การก๊อปค่า

## ขั้นที่ 2 — backend บน Railway

1. **+ New → GitHub Repo** → เลือก `S-Nithit/LEBIS-Project`
2. ตั้ง **Root Directory** เป็น `backend-api`
   ที่ **Settings → Source → Root Directory**
   Railway จะเจอ `Dockerfile` ในนั้นแล้ว build ให้เอง ไม่ต้องตั้ง build command

   🔴 **ต้องกดในหน้าเว็บเท่านั้น** Railway CLI ไม่มีคำสั่งตั้งค่านี้
   (ตรวจครบทุกคำสั่งของ CLI 4.44 แล้ว) และถ้าไม่ตั้ง build จะล้มทุกครั้ง
   — ดูหัวข้อแก้ปัญหาท้ายไฟล์

   ตรวจด้วยว่า **Branch** เป็น `dev` ไม่ใช่ `main`
3. แท็บ **Variables** ใส่ตัวแปรตามตารางนี้

   | ตัวแปร | ค่าที่ใส่ | หมายเหตุ |
   |---|---|---|
   | `DATABASE_URL` | `${{Postgres.DATABASE_URL}}` | อ้างอิงจากบริการ Postgres โดยตรง ไม่ต้องก๊อปรหัสผ่านมาวาง |
   | `JWT_SECRET` | ค่าสุ่มใหม่ 64 ตัวอักษร | **ต้องเป็นคนละค่ากับ `.env` ในเครื่อง** — อ่านเหตุผลข้างล่าง |
   | `SEED_DEMO_ACCOUNTS` | `false` | **สำคัญ** ถ้าลืมตั้ง ระบบจะสร้างบัญชีทดลองที่รหัสผ่านอยู่ในโค้ดบนอินเทอร์เน็ต |
   | `ADMIN_EMAIL` | อีเมลของผู้ดูแลระบบ | ใช้เข้าหน้าผู้ดูแลระบบบนเว็บจริง · ต้องเป็นโดเมนปกติ ห้าม `.local` หรือ `.test` |
   | `ADMIN_PASSWORD` | **รหัสใหม่ ไม่ซ้ำกับในเครื่อง** | รหัสนี้เปิดสิทธิ์สูงสุดของระบบ อ่านเหตุผลข้างล่าง |

   สร้างค่า `JWT_SECRET` กับ `ADMIN_PASSWORD` ใหม่ด้วยคำสั่งพวกนี้
   แล้วก๊อปไปวางในช่องของ Railway

   ```bash
   openssl rand -hex 32      # สำหรับ JWT_SECRET
   openssl rand -base64 18   # สำหรับ ADMIN_PASSWORD
   ```

   บัญชีผู้ดูแลระบบถูกสร้างครั้งเดียวตอนสตาร์ทครั้งแรกที่เจอค่าทั้งสอง
   หลังจากนั้นการแก้ `ADMIN_PASSWORD` แล้วรีสตาร์ท**จะไม่เปลี่ยนรหัสของบัญชีเดิม**
   (ระบบใช้ `ON CONFLICT DO NOTHING` เพื่อไม่ไปทับสิ่งที่แก้ไว้ในฐานข้อมูล)
   ถ้าต้องเปลี่ยนรหัส ให้เปลี่ยนผ่านฐานข้อมูลโดยตรง

   ไม่ต้องตั้ง `PORT` — Railway กำหนดมาให้เอง และ `Dockerfile` อ่านค่านั้นแล้ว

4. แท็บ **Settings → Networking → Generate Domain** เพื่อขอ URL สาธารณะ
   ของโปรเจกต์นี้ได้มาเป็น `https://lebis-project-production.up.railway.app`
5. ตรวจว่าขึ้นจริง — เปิด `<URL>/api/health` ต้องได้

   ```json
   {"status":"ok","message":"backend ทำงานปกติ"}
   ```

   และ `<URL>/docs` ต้องเห็นหน้า Swagger UI

### ทำไม `JWT_SECRET` ตอน production ต้องเป็นค่าใหม่

กุญแจนี้คือสิ่งเดียวที่พิสูจน์ว่า token ใบหนึ่งออกโดยระบบเราจริง ใครถือกุญแจ
สร้าง token ปลอมเป็นผู้ใช้คนไหนก็ได้ รวมถึง `admin`

ค่าใน `.env` บนเครื่องพัฒนาผ่านมือคนหลายคน อยู่ในเครื่องที่ลงโปรแกรมอะไรก็ไม่รู้
และอาจหลุดไปอยู่ในสกรีนช็อตหรือหน้าจอตอนสอนงาน ถ้าใช้ค่าเดียวกัน การรั่วบนเครื่อง
พัฒนาเครื่องใดเครื่องหนึ่ง = ระบบจริงถูกปลอม token ได้ทันที

ค่าที่ตั้งบน Railway ควรถูกสร้างขึ้นที่นั่นครั้งเดียว ไม่ต้องมีใครเก็บสำเนาไว้
ถ้าจำเป็นต้องเปลี่ยน (เช่นสงสัยว่าหลุด) ให้สร้างใหม่แล้ววางทับ ผู้ใช้ทุกคนจะถูก
ให้เข้าสู่ระบบใหม่ ซึ่งเป็นผลที่ถูกต้อง

### ทำไม `ADMIN_PASSWORD` ต้องเป็นคนละตัวกับในเครื่อง

เหตุผลเดียวกับ `JWT_SECRET` แต่ตรงกว่า — รหัสนี้เข้าหน้าผู้ดูแลระบบได้โดยตรง
ค่าในเครื่องของทีมอยู่ในไฟล์ `.env` บนเครื่องสี่เครื่องที่เราไม่ได้คุมทั้งหมด
และถูกพิมพ์ให้ดูตอนสอนงานได้ง่ายๆ ถ้าใช้ค่าเดียวกัน คนที่เห็นรหัสบนเครื่องพัฒนา
ก็เข้าระบบจริงได้ทันที

บัญชีผู้ดูแลระบบบน production ควรมีคนเดียวที่รู้รหัส และเก็บไว้ในที่เก็บรหัสผ่าน
ไม่ใช่ในแชทของทีม

## ขั้นที่ 3 — frontend บน Vercel

1. [vercel.com](https://vercel.com) → **Add New → Project** → เลือก repo เดียวกัน
2. ตั้ง **Root Directory** เป็น `nextjs`
   Framework Preset จะขึ้นเป็น Next.js เอง ไม่ต้องแก้ build command
   ค่านี้ก็ต้องกดในหน้าเว็บเหมือนกัน

3. 🔴 **เปลี่ยน Production Branch เป็น `dev`**
   ที่ **Settings → Environments → Production**

   Vercel ตั้ง Production Branch เป็น `main` มาให้เองตอนสร้างโปรเจกต์
   ถ้าไม่เปลี่ยน การ push เข้า `dev` จะถูก deploy เป็น Preview เท่านั้น
   เว็บจริงจะค้างอยู่ที่โค้ดของ `main` ซึ่งเก่ากว่า และจะดูเหมือนว่า
   "แก้โค้ดแล้วเว็บไม่อัปเดต" โดยไม่มี error ให้เห็นเลย
4. **Environment Variables** ใส่ตัวเดียว

   | ตัวแปร | ค่าที่ใส่ |
   |---|---|
   | `BACKEND_URL` | URL ของ backend จากขั้นที่ 2 — ของโปรเจกต์นี้คือ `https://lebis-project-production.up.railway.app` |

   ใส่ **ไม่ต้องมี** `/api` ต่อท้าย และไม่ต้องมี `/` ปิดท้าย
   เพราะ `next.config.mjs` ต่อ `/api/:path*` ให้เองอยู่แล้ว

5. กด **Deploy**

> ⚠️ `BACKEND_URL` ถูกอ่านตอน build ไม่ใช่ตอนรัน ถ้าแก้ค่านี้ทีหลัง
> ต้องสั่ง **Redeploy** ค่าใหม่ถึงจะมีผล การกด Save เฉยๆ ไม่พอ

### ไม่ต้องตั้ง CORS และไม่ต้องมี `NEXT_PUBLIC_API_URL`

หน้าเว็บเรียก path สัมพัทธ์เสมอ (`fetch("/api/items")`) แล้ว Next.js ฝั่งเซิร์ฟเวอร์
ส่งต่อไปที่ backend ให้ คำขอจึงไม่เคยข้ามโดเมนในสายตาเบราว์เซอร์ ผลพลอยได้คือ
URL ของ backend ไม่โผล่ในโค้ดฝั่งเบราว์เซอร์เลย

## ขั้นที่ 4 — ตรวจหลัง deploy

| ตรวจอะไร | คาดหวัง |
|---|---|
| เปิดโดเมนของ Vercel | เห็นหน้าเว็บ |
| สมัครสมาชิกใหม่ที่ `/register` | สมัครผ่าน ได้ token กลับมา และถูกพาไปหน้าแรก |
| login ด้วยบัญชีที่เพิ่งสมัคร | ผ่าน |
| login ด้วยรหัสผิด | ขึ้นข้อความผิดพลาด ได้ 401 ไม่ใช่ 500 |
| `<backend>/api/auth/me` โดยไม่ส่ง token | 401 |
| `<backend>/api/health/protected` ด้วย token ของผู้ใช้ทั่วไป | 403 |
| ล็อกของ backend ตอนสตาร์ท | ต้องมีบรรทัด `ข้ามการใส่บัญชีทดลอง (SEED_DEMO_ACCOUNTS=false)` และบรรทัด `บัญชีผู้ดูแลระบบพร้อมใช้งาน: <อีเมลที่ตั้งไว้>` |
| ลอง login ด้วย `demo@example.com` / `password` | **ต้องไม่ผ่าน** ถ้าผ่านแปลว่าลืมตั้ง `SEED_DEMO_ACCOUNTS=false` |
| login ด้วย `ADMIN_EMAIL` แล้วเปิดหน้าผู้ดูแลระบบ | ต้องเข้าได้ — หน้านี้เป็นหนึ่งในหน้าที่โจทย์บังคับ ต้องเข้าได้บนลิงก์จริง |
| สมัครสมาชิกผ่าน **โดเมนของ Vercel** แล้วไปดูว่ามีแถวเพิ่มในฐานข้อมูลของ Railway | ต้องเจอแถวนั้น — ข้อนี้คือข้อเดียวที่พิสูจน์ว่า rewrite ของ Vercel ชี้มาที่ Railway ถูกจริง ไม่ใช่แค่ทั้งสองฝั่งขึ้นได้แยกกัน · อย่าลืมลบบัญชีที่ใช้ทดสอบออก |

บรรทัดสุดท้ายสำคัญที่สุดในตาราง — เป็นการตรวจว่าไม่มีบัญชีที่ทุกคนรู้รหัสผ่าน
ค้างอยู่บนระบบจริง

ถ้าเผลอ deploy ไปแล้วโดยยังไม่ได้ปิด ให้ตั้ง `SEED_DEMO_ACCOUNTS=false`
แล้วลบสองบัญชีนั้นทิ้งด้วยมือ (การตั้งค่าอย่างเดียวไม่ลบของที่ถูกสร้างไปแล้ว)

```sql
DELETE FROM users WHERE email = 'demo@example.com';
```

(บัญชีผู้ดูแลระบบไม่ต้องลบ เพราะรหัสของมันมาจาก `ADMIN_PASSWORD` ที่ตั้งบน Railway
ไม่ได้อยู่ในโค้ด)

## ขั้นที่ 5 — แจ้งเตือน LINE (Messaging API)

ไม่ตั้งขั้นนี้ ระบบยังรันได้ทุกอย่าง แค่ไม่ส่ง LINE
(`/api/line/test` กับ `/api/line/digest` จะตอบ 503 `line_not_configured`)

### 5.1 สร้าง channel — ทำในหน้าเว็บของ LINE เท่านั้น

> ตั้งแต่ 4 ก.ย. 2567 (2024) LINE ไม่ให้สร้าง Messaging API channel จาก Developers Console ตรงๆ แล้ว
> ต้องสร้าง LINE Official Account ก่อน แล้วเปิด Messaging API จากหน้าจัดการ OA
> (ที่มา: developers.line.biz/en/docs/messaging-api/getting-started)

1. [manager.line.biz](https://manager.line.biz) → เข้าสู่ระบบด้วยบัญชี LINE → **สร้างบัญชี LINE Official Account**
   ตั้งชื่อ `LEBIS` กรอกฟอร์มให้ครบ
2. ในหน้าจัดการ OA → **ตั้งค่า (Settings) → Messaging API → เปิดใช้ Messaging API**
   ระบบจะให้เลือกหรือสร้าง Provider ตั้งชื่อ `LEBIS` — ขั้นนี้คือการสร้าง channel
3. [developers.line.biz/console](https://developers.line.biz/console/) → เข้าด้วยบัญชีเดียวกัน → Provider `LEBIS` → คลิก channel
4. แท็บ **Basic settings** → คัด **Channel secret** (ต้องเป็น Admin ของ channel)
5. แท็บ **Messaging API** → **Channel access token (long-lived)** → กด **Issue** แล้วคัด token
   (แบบ long-lived ไม่หมดอายุ ระบบของเราใช้แบบนี้)
6. แท็บเดียวกัน → **Webhook URL** กด **Edit** ใส่
   `https://lebis-project-production.up.railway.app/api/line/webhook` กด **Update**
   → กด **Verify** ต้องขึ้น **Success** (ระบบตอบ 200 กับ event ว่างที่ LINE ส่งมาทดสอบ)
   → เปิด **Use webhook**
   ⚠️ ถ้า Verify ไม่ผ่าน เช็คว่าตั้ง `LINE_CHANNEL_SECRET` บน Railway แล้ว (ขั้น 5.2)
   ถ้ายังไม่ตั้ง ระบบตอบ 503 ตั้งใจให้เป็นแบบนั้น
7. กลับไปหน้าจัดการ OA → ตั้ง **ข้อความต้อนรับ (Greeting messages)** และ
   **ตอบกลับอัตโนมัติ (Auto-reply messages)** เป็น **Disabled**
   ไม่งั้น OA จะตอบข้อความสำเร็จรูปซ้อนกับข้อความของเรา
8. แท็บ **Messaging API** ของ Developers Console มี QR code ไว้แอด OA เป็นเพื่อน

> 🔴 token กับ secret คือกุญแจเข้า OA ของเรา ห้ามวางในแชท ห้ามใส่ในไฟล์ที่ขึ้น git
> ใส่ตรงในหน้า Variables ของ Railway และในไฟล์ `.env` ของเครื่องตัวเองเท่านั้น

### 5.2 ตั้งค่าบน Railway (service backend)

ทำหลังข้อ 5 แต่**ก่อนข้อ 6** ของ 5.1 — ปุ่ม Verify ต้องใช้ secret ที่ตั้งไว้แล้ว
ตั้งเสร็จ Railway จะ deploy ใหม่เอง รอให้ `/api/health` ตอบ 200 ก่อนค่อยกด Verify

| ตัวแปร | ค่า |
|---|---|
| `LINE_CHANNEL_ACCESS_TOKEN` | token จากข้อ 5 |
| `LINE_CHANNEL_SECRET` | secret จากข้อ 4 |
| `LINE_ADD_FRIEND_URL` | ลิงก์แอดเพื่อนของ OA (ไม่ใส่ก็ได้) หน้าตั้งค่าจะโชว์ปุ่มแอดเพื่อนให้ |

### 5.3 ตรวจหลังตั้งค่า

| ตรวจอะไร | คาดหวัง |
|---|---|
| ผู้ใช้ Free เรียก `POST /api/line/digest` | **403** `tier_required` — อาจารย์เทสข้อนี้สด |
| ผู้ใช้ Pro เรียก `POST /api/line/link-code` | ได้รหัส 8 ตัว |
| แอด OA เป็นเพื่อนแล้วพิมพ์รหัสนั้นในแชท | OA ตอบ "ผูกบัญชีกับร้าน ... แล้ว" |
| `POST /api/line/test` | ได้ข้อความทดสอบใน LINE |
| มีใบเช่าที่ครบวันนี้หรือพรุ่งนี้ แล้วเรียก `POST /api/line/digest` | ได้ข้อความสรุปใน LINE |

## เรื่องที่ต้องรู้เกี่ยวกับฐานข้อมูลตอน deploy

**ตารางถูกสร้างตอน backend สตาร์ท** `setup_db()` รันทุกครั้งที่สตาร์ทและใช้
`CREATE TABLE IF NOT EXISTS` ทั้งหมด จึงปลอดภัยกับฐานข้อมูลเปล่าของ Railway
ไม่ต้องรัน migration หรือนำเข้าไฟล์ SQL อะไรก่อน

**โปรเจกต์นี้ไม่มีเครื่องมือ migration** ตอนเรียนอยู่ วิธีเปลี่ยนสคีมาคือ
`docker compose down -v` แล้วขึ้นใหม่ ซึ่งลบข้อมูลทิ้งหมด — ทำแบบนั้นกับฐานข้อมูล
จริงไม่ได้ ถ้าต้องแก้สคีมาหลัง deploy แล้ว ให้เพิ่มคำสั่ง `ALTER TABLE ... IF NOT
EXISTS` ต่อท้ายใน `setup_db()` แทนการแก้ `CREATE TABLE` เดิม เพราะ
`CREATE TABLE IF NOT EXISTS` จะข้ามตารางที่มีอยู่แล้ว การแก้บล็อกนั้นไม่มีผลใดๆ
กับฐานข้อมูลที่สร้างตารางไปแล้ว (คอลัมน์ที่เพิ่มทีหลังในตาราง `users` ก็ทำด้วย
วิธีนี้ ดู `ALTER_USERS` ใน `database.py`)

**วิธีเข้าไปดูฐานข้อมูลจริง** Postgres ของ Railway เปิดเฉพาะเครือข่ายภายใน
(`postgres.railway.internal`) ต่อจากเครื่องตัวเองตรงๆ ไม่ได้ และโปรเจกต์นี้
ไม่ได้เปิด TCP proxy ไว้ วิธีที่ใช้อยู่คือ ssh เข้าไปที่ backend แล้วสั่งจากข้างใน

```bash
railway ssh --service LEBIS-Project -- python -c "import database; print(1)"
```

ครั้งแรกต้องมี SSH key ในเครื่องก่อน (`ssh-keygen -t ed25519`) แล้วลงทะเบียน
ด้วย `railway ssh keys add` · สคริปต์ที่มีวงเล็บหรือเครื่องหมายคำพูดจะโดน
shell ฝั่งโน้นตีความผิด ให้ส่งแบบ base64 แทน
`railway ssh --service <ชื่อ> -- echo <base64> \| base64 -d \| python -`

**รันหลายอินสแตนซ์พร้อมกันยังไม่รองรับ** ถ้าขยายเป็นหลายอินสแตนซ์ในอนาคต
สองตัวที่สตาร์ทพร้อมกันอาจสร้างตารางชนกัน ตอนนี้ใช้อินสแตนซ์เดียวจึงไม่มีปัญหา

**ค่าเชื่อมต่อมาจากไหน** `database.py` ใช้ `DATABASE_URL` ก่อนเสมอ ถ้าไม่มี
ค่อยประกอบ URL จาก `POSTGRES_*` แบบที่ compose ใช้ และรองรับทั้ง `postgres://`
กับ `postgresql://` รวมถึงแปลง `sslmode=require` ที่บางผู้ให้บริการติดมาท้าย URL
ให้เป็นรูปที่ asyncpg เข้าใจ

## แก้ปัญหาที่เจอจริงตอน deploy ครั้งแรก

### Railway build ล้มโดยไม่มี log อะไรเลย

อาการ: deployment ขึ้น FAILED ภายในไม่กี่วินาที และ build log มีบรรทัดเดียวคือ
`scheduling build on Metal builder "builder-xxxxx"` แล้วจบ ไม่มี error ให้อ่าน

สาเหตุ: **ยังไม่ได้ตั้ง Root Directory** Railway จึงดึงทั้ง repo มา build
แล้วที่รากไม่มีทั้ง `requirements.txt` และ `package.json` (สองไฟล์นั้นอยู่ใน
`backend-api/` กับ `nextjs/`) มันเลยล้มตั้งแต่ขั้นตัดสินใจว่าจะ build อะไร
ซึ่งเป็นขั้นก่อนที่ log ของ build จะเริ่มบันทึก

วิธีแก้: ตั้ง Root Directory เป็น `backend-api` ตามขั้นที่ 2 แล้ว deploy ใหม่

### push เข้า dev แล้วเว็บจริงไม่อัปเดต

สาเหตุ: Production Branch ของ Vercel ยังเป็น `main`
วิธีแก้: Settings → Environments → Production → เปลี่ยนเป็น `dev`

### ค่าไหนตั้งด้วย CLI ได้บ้าง

| งาน | Railway CLI | ต้องกดในหน้าเว็บ |
|---|---|---|
| ผูกโปรเจกต์ · เพิ่ม Postgres · ตั้ง env · ขอ domain · อ่าน log · ssh | ✅ | — |
| Root Directory | ❌ | ✅ |
| Production Branch (Vercel) | ❌ | ✅ |
