## วิดีโอ Data — 0:00–3:00 แนะนำทีมและปัญหา

**บนจอ:** หน้าแรกของ notebook (ตารางอัลกอริทึม 3 กลุ่ม) หรือสไลด์ชื่อทีม

**0:00–0:40 แนะนำทีม**
- "สวัสดีครับ เราคือทีม LEBIS ผม นิธิศ รับส่วน hash table กับการเพิ่ม–ลบของ"
- ให้แต่ละคนพูดชื่อตัวเองสั้นๆ: นีโอ — ค้นหากับนับ · กุล — เรียงลำดับกับจัดกลุ่ม
  (ซีไม่ได้ลงวิชานี้ ไม่ต้องอยู่ในวิดีโอนี้)

**0:40–2:00 ปัญหา**
- "ลองนึกถึงร้านเช่ากล้องเล็กๆ มีคน 1–3 คน ของเป็นร้อยชิ้น จดลงกระดาษหรือ Excel"
- ปัญหาที่ร้านเจอทุกวันมี 3 อย่าง
  1. ลูกค้าถามว่ากล้องตัวนี้ว่างมั้ย ต้องเดินไปดูที่ชั้น
  2. ไม่รู้ว่าใครยืมอะไรไป ของคืนช้ากว่าจะรู้ตัวก็หลายวัน
  3. ไม่รู้ว่าของชิ้นไหนทำเงิน
- "ทั้งสามข้อคือคำถามเรื่องข้อมูล: หาของ นับของ เรียงของ วิชานี้คือเครื่องมือที่ตอบคำถามพวกนี้"

**2:00–3:00 ภาพรวมว่าใครทำอะไร**
- "เราแบ่งเป็น 3 กลุ่มอัลกอริทึม แต่ละคนเขียนเองคนละตัว ไม่ใช้ของสำเร็จรูป"
  - hash table (คิม) — ใส่ ลบ ค้นด้วยรหัส
  - binary search (นีโอ) — ค้นหาเป็นช่วง เช่น ของที่ครบกำหนดก่อนวันนี้
  - merge sort (กุล) — เรียงตามวันคืน
- "ทุกคนวัดบนข้อมูล 4 ชุดเดียวกัน A ถึง D ชุดใหญ่สุดมี 1,000 รายการ ตัวเลขของสามคนจึงเทียบกันได้"
- "และ merge sort กับ binary search ในนี้คือไฟล์เดียวกับที่ระบบเว็บจริงใช้เรียงและหาใบที่เลยกำหนด ไม่ได้เขียนซ้ำสองรอบ"
  (อย่าพูดว่า hash table อยู่ในเว็บ — ในเว็บใช้ index ของฐานข้อมูลหาของด้วยรหัส hash table วัดผลใน notebook อย่างเดียว)

## วิดีโอ Data — 3:00–8:00 hash table

**บนจอ:** notebook หัวข้อ 2–7 สลับกับ flowchart 3 ไฟล์ใน `docs/data-course/flowcharts/`

**3:00–4:00 โครงสร้างข้อมูล** (notebook หัวข้อ 2 · Flowchart 1)
- "ของ 1 ชิ้นเก็บเป็น dict 8 ฟิลด์ รหัส ชื่อ หมวด จำนวนทั้งหมด จำนวนว่าง คนยืม วันคืน สถานะ"
- "เราเก็บของสองที่คู่กัน list เก็บตัวข้อมูลจริง ส่วน hash table เก็บแค่ รหัส → ตำแหน่งใน list"
- "ทำไมไม่เก็บ hash table อย่างเดียว เพราะ hash table ไม่มีลำดับ
  merge sort ของกุลกับ binary search ของนีโอต้องใช้ list ที่เรียงได้"

**4:00–5:30 hash function + การชน** (notebook หัวข้อ 3–4 · Flowchart 2)
- "ฟังก์ชันแฮชคือ polynomial rolling hash ฐาน 31 คูณสะสมทีละตัวอักษร"
- "ทำไมไม่บวกรหัสตัวอักษรเฉยๆ — เพราะ CAM-01 กับ CAM-10 จะได้ค่าเท่ากัน ร้านใช้รหัสแบบนี้จริง"
- "การชนคือรหัสต่างกันแต่ตกถังเดียวกัน เลี่ยงไม่ได้ เราแก้ด้วย chaining ถังหนึ่งเก็บได้หลายตัวเป็นโซ่"
- ชี้ Flowchart 2 เส้นทาง "ถังนี้ว่าง? → ไม่ว่าง → ชน → ต่อท้ายโซ่"
- "พอข้อมูลเกิน 70% ของจำนวนถัง เราขยายถังเป็นสองเท่าแล้วคำนวณตำแหน่งใหม่ทุกตัว"

**5:30–6:30 ทำไม O(1) เป็นค่าเฉลี่ย** (notebook หัวข้อ 4 ตารางที่ห้ามขยาย)
- "ถ้าทุกรหัสไปกองถังเดียว ตารางจะเหลือโซ่เส้นเดียว ค้นหาก็กลายเป็นไล่ทีละตัว = O(n)"
- ชี้ตารางที่ห้ามขยาย: "8 ถัง ของ 120 ชิ้น โซ่เฉลี่ยถังละ 15 ตัว ยาวสุด 17 ตัว ส่วนตารางที่ขยายตามปกติยาวสุดแค่ 3 ตัว ยิ่งใส่เพิ่ม โซ่ยิ่งยาวตาม n นี่คือกรณีแย่สุด"
- "O(1) ไม่ได้มาฟรี มาจากแฮชที่กระจายดี กับการขยายตาราง ขาดข้อไหนก็ไหลลงไปเป็น O(n)"

**6:30–7:30 ผลวัดจริงบนชุด A–D** (**`LEBIS_Final.ipynb` ส่วนที่ 2** ตาราง H1–H4 — ไม่ใช่ notebook ของคิมคนเดียว ตัวเลขเป็นคนละรอบ)
- "ชุดเล็ก 10 รายการ วน list เร็วกว่าด้วยซ้ำ เพราะไล่ 10 ตัวถูกกว่าคำนวณแฮช
  Big-O บอกตอน n โต ไม่ได้บอกว่าใครชนะตอน n น้อย"
- "ชุด D 1,000 รายการ hash table ค้นเร็วกว่าวน list **14.2 เท่า** · เพิ่มเร็วกว่า **3.5 เท่า** · ลบเร็วกว่า **8.8 เท่า**"
- "ชุด D ชนกัน **374 ครั้ง** แต่โซ่ยาวสุดแค่ **3** เพราะขยายตาราง **8 ครั้ง** load factor จบที่ **0.488**
  การชนไม่ใช่ปัญหา ถ้าไม่ปล่อยให้โซ่ยาว"
- "dict ของ Python ยังเร็วกว่าเรา เพราะเขียนด้วยภาษา C แต่เป็น O(1) เหมือนกัน ต่างกันแค่ค่าคงที่"

**7:30–8:00 ลบแบบ swap-and-pop + ส่งต่อ** (Flowchart 3)
- "ลบตัวกลาง list ตรงๆ เป็น O(n) เพราะต้องเลื่อนทุกตัวข้างหลัง เราเลยยกตัวท้ายมาวางทับ แก้ดัชนีตัวเดียว = O(1)"
- "ต่อไปนีโอจะเล่าว่าเราค้นหาของที่ครบกำหนดยังไง ซึ่ง hash table ทำไม่ได้"

## อาจารย์น่าจะถามอะไร (เตรียมคำตอบไว้)

| คำถาม | คำตอบสั้น |
|---|---|
| ทำไมไม่ใช้ dict ของ Python | โจทย์ให้เขียนเอง และการเขียนเองทำให้อธิบายได้ว่า O(1) มาจากไหน dict ใช้เป็นตัวเทียบเท่านั้น |
| ทำไม 0.7 | ต่ำเกินเปลืองที่และขยายบ่อย สูงเกินโซ่ยาวค้นช้า 0.7 อยู่ตรงกลาง |
| ทำไม chaining ไม่ใช่ open addressing | chaining อ่านง่ายกว่า และลบได้ตรงๆ open addressing ต้องใส่เครื่องหมายว่าช่องนี้เคยมีของ |
| ขยายตารางเป็น O(n) แล้วทำไมยังบอกว่าเพิ่มเป็น O(1) | ขยายเกิดเฉพาะตอนข้อมูลเพิ่มเป็นเท่าตัว เฉลี่ยต่อการเพิ่มหนึ่งครั้งจึงเป็นค่าคงที่ (amortized O(1)) |
| ทำไมชุดเล็ก list ชนะ | ค่าคงที่ของการคำนวณแฮชแพงกว่าการไล่ 10 ตัว Big-O พูดถึงตอน n โต |
| กรณีแย่สุดเกิดได้จริงมั้ย | เกิดได้ถ้าคนรู้สูตรแฮชแล้วตั้งใจเลือกรหัสให้ชนกัน ของจริงจึงผสมค่าสุ่มเข้าไป Python ก็ทำ |
