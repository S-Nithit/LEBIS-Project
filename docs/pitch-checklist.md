พรีเซนต์บนเวที + อาจารย์เทสระบบสด (live edge-case testing)
อาจารย์จะลองทำสิ่งที่ระบบ**ต้องไม่ยอม** ถ้าหลุดบนเวทีคือแก้ไม่ทันแล้ว

## บัญชีที่ใช้

| บัญชี | สถานะ | ใช้โชว์อะไร |
|---|---|---|
| `demo-free@lebis-demo.com` | ฟรี · ของครบ 50/50 | กรณีที่ต้องโดนบล็อกทั้งหมด |
| `demo-pro@lebis-demo.com` | Pro · ผูก LINE แล้ว · เลยกำหนด 5 ใบ | ฟีเจอร์ Pro ครบ |

🔴 **ห้ามอัปเกรด demo-free เป็น Pro** ก่อนพรีเซนต์ — ถ้าอัปเกรดไปแล้ว จะโชว์กรณีโดนบล็อกไม่ได้
ถ้าอาจารย์อยากเห็นการอัปเกรด ให้กดใน demo-free **หลังจาก**โชว์กรณีโดนบล็อกเสร็จแล้วเท่านั้น

## กรณีที่อาจารย์น่าจะลอง

| ลองอะไร | ต้องเห็น | ทำไมไม่หลุด |
|---|---|---|
| Free เพิ่มอุปกรณ์ชิ้นที่ 51 | กล่องแดง "ครบตามจำนวนของแพ็กเกจฟรีแล้ว" · API ตอบ 403 | เช็คจำนวนที่เซิร์ฟเวอร์ ไม่ใช่แค่ซ่อนปุ่ม |
| Free ยิง API ตรงผ่าน `/docs` | 403 เหมือนกัน | `require_tier("pro")` อยู่หน้า route |
| Free กด LINE / ส่งออก CSV | 403 | `require_tier("pro")` |
| Free / Pro เข้าหน้า admin | 403 | `require_role("admin")` |
| ไม่ login หรือใช้ token ปลอม | 401 | ตรวจลายเซ็น JWT ทุกคำขอ |
| Free ดูรายงาน | ได้แค่ 7 วันล่าสุด (`limited: true`) | เซิร์ฟเวอร์ตัดช่วงวันให้เอง |
| อัปเกรดแล้วกดยืนยันซ้ำหลายครั้ง | ได้ Pro ครั้งเดียว ไม่สร้างรายการซ้ำ | ล็อกแถวใน transaction (ดู Design Doc 4) |
| เช่าของที่ถูกยืมไปหมดแล้ว หรือของที่ชำรุด | 409 "ถูกยืมไปหมดแล้ว" / "ชำรุดอยู่" | เช็ค `available` และ `status` ก่อนบันทึก |
| กดรับคืนใบเดิมซ้ำ | 409 "รายการนี้รับคืนไปแล้ว" | ของไม่ถูกบวกกลับขึ้นชั้นสองรอบ |
