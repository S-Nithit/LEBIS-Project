## ร้านเช่าอุปกรณ์เจอปัญหาเดียวกันหมด

ร้านเช่ากล้อง ร้านเช่าเครื่องมือช่าง ร้านเช่าของงานอีเวนต์ ส่วนใหญ่มีพนักงาน 1-3 คน
และยังจดของลงสมุดหรือไฟล์ Excel ที่แชร์กันในไลน์กลุ่ม ผลที่ตามมามี 3 อย่าง

**ไม่รู้ว่าของเหลืออะไรบนชั้น** ลูกค้าโทรมาถามว่ามีของว่างมั้ย ต้องวางสายไปเดินนับก่อน

**ตามของคืนไม่ทัน** ของเลยกำหนดไปหลายวันกว่าจะรู้ตัว ของหายหนึ่งชิ้นคือเงินจริงที่หายไป

**ไม่รู้ว่าของชิ้นไหนทำเงิน** ซื้อของใหม่เข้าร้านด้วยความรู้สึก ไม่ใช่ด้วยตัวเลข

| | |
|---|---|
| **เห็นสต็อกตามจริง** | ของทุกชิ้นมีรหัส รู้ทันทีว่าว่างกี่ชิ้น ถูกยืมไปกี่ชิ้น ชำรุดกี่ชิ้น |

## ติดตั้งบนเครื่องตัวเอง 3 คำสั่ง

ต้องมี Docker Desktop เปิดอยู่ก่อน

```bash
git clone https://github.com/S-Nithit/LEBIS-Project.git
cd LEBIS-Project && cp .env.example .env
docker compose up --build
```

เปิดดูได้ที่

| ปลายทาง | ที่อยู่ |
|---|---|
| หน้าเทส API | http://localhost:8000/docs |
| เช็กสถานะระบบ | http://localhost:8000/health |
| ฐานข้อมูล | localhost:**5433** |
| หน้าบ้าน | http://localhost:3000 (ยังไม่มีในเฟสนี้) |

### ⚠️ ฐานข้อมูลอยู่ที่พอร์ต 5433 ไม่ใช่ 5432

หลายเครื่องมี PostgreSQL ตัวอื่นจองพอร์ต 5432 อยู่ก่อนแล้ว ถ้าใช้พอร์ตเดียวกันจะขึ้น
`port is already allocated` แล้ว container ไม่ยอมสตาร์ท เราจึงเปิดออกมาที่ **5433** แทน

- ต่อจากโปรแกรมจัดการฐานข้อมูลบนเครื่อง เช่น DBeaver หรือ TablePlus → ใช้ `localhost:5433`
- ส่วนค่า `DATABASE_URL` ที่ backend ใช้ ยังเป็น `db:5432` เหมือนเดิม **ห้ามแก้เป็น 5433**
  เพราะ backend คุยกับฐานข้อมูลผ่านเครือข่ายภายในของ Docker ซึ่งมองเห็นพอร์ตจริงคือ 5432
  เลข 5433 เป็นเรื่องของเครื่องเราที่มองจากข้างนอกเข้าไปเท่านั้น

### คำสั่งที่ใช้บ่อย

```bash
docker compose up --build          # ขึ้นทั้งระบบ
docker compose down                # ปิด (ข้อมูลยังอยู่)
docker compose down -v             # ปิดแล้วล้างฐานข้อมูลทิ้ง เริ่มใหม่จากศูนย์
docker compose logs -f backend     # ดู log หลังบ้านแบบสด
docker compose exec db psql -U postgres -d lebis -c "\dt"   # ดูรายชื่อตาราง
```
