# LEBIS

**รู้ทันทีว่าของอยู่ไหน ใครถือไป และครบกำหนดคืนเมื่อไหร่**

ระบบจัดการสต็อกและการยืม-คืนสำหรับร้านให้เช่าอุปกรณ์ขนาดเล็ก
— ร้านเช่ากล้อง ร้านเช่าเครื่องมือช่าง ร้านเช่าอุปกรณ์จัดงาน

## ปัญหาที่ LEBIS แก้

ร้านเช่าอุปกรณ์ขนาด 1–3 คนส่วนใหญ่ยังจดสต็อกในสมุดหรือไฟล์ Excel ที่แชร์กัน
แล้วเจอปัญหาเดิมทุกร้าน

| ปัญหา | ผลที่ตามมา | LEBIS ทำอะไร |
|---|---|---|
| ไม่รู้ว่าตอนนี้ของเหลือบนชั้นกี่ชิ้น | รับจองของที่ไม่มีของ ต้องโทรขอโทษลูกค้า | หน้าจอเดียวเห็นของว่างจริงตามเวลาจริง |
| ลืมว่าใครยืมอะไรไป ตามคืนช้า | ของหายคือเงินหาย | ทุกใบยืมผูกลูกค้า + เบอร์โทร + กำหนดคืน |
| ไม่รู้ว่าอุปกรณ์ตัวไหนทำเงิน | ซื้อของผิดตัวซ้ำๆ | รายงานยอดหมุนเวียนต่ออุปกรณ์ |

## ฟีเจอร์หลัก

- **คลังอุปกรณ์** — เพิ่ม/แก้อุปกรณ์ แยกหมวด กำหนดค่าเช่าต่อวัน ตัดยอดของว่างอัตโนมัติ
- **ใบยืม–คืน** — บันทึกว่าใครยืมอะไรไป ครบกำหนดวันไหน กดคืนแล้วของกลับเข้าคลังทันที
- **แจ้งเตือนผ่าน LINE** — เตือนก่อนครบกำหนดคืน ไม่ต้องนั่งไล่ดูสมุดเอง
- **รายงานของที่ทำเงิน** — อุปกรณ์ตัวไหนถูกยืมบ่อย ตัวไหนนอนอยู่บนชั้น
- **ส่งออกไฟล์ CSV** — เอาข้อมูลไปทำบัญชีต่อได้
- **ระบบสมาชิกและเก็บเงินรายเดือน** — แพ็กเกจฟรีกับแพ็กเกจ Pro

### แพ็กเกจ

| | ฟรี | Pro — 299 บาท/เดือน |

| แจ้งเตือนผ่าน LINE | ✗ | ✓ |
| ย้อนดูรายงาน | 7 วันล่าสุด | ทั้งหมด |
| ส่งออกไฟล์ CSV | ✗ | ✓ |

ข้อจำกัดของแพ็กเกจถูกบังคับที่ฝั่งเซิร์ฟเวอร์ (FastAPI dependency) ไม่ใช่แค่ซ่อนปุ่มในหน้าเว็บ

## เทคโนโลยีที่ใช้

| ส่วน | เทคโนโลยี |

| Frontend | Next.js (Pages Router) · JavaScript · Tailwind CSS · shadcn-style components |

## วิธีติดตั้งและรัน

ต้องมี **Docker Desktop** ติดตั้งไว้ก่อน นอกนั้นไม่ต้องลงอะไรเพิ่มเลย

```bash
git clone https://github.com/S-Nithit/LEBIS-Project.git
cd LEBIS-Project

# สร้างกุญแจที่ใช้เซ็น JWT ของตัวเอง (ทำครั้งเดียวต่อเครื่อง)
# ไฟล์ .env ไม่ขึ้น git ทุกคนจึงต้องสร้างเองบนเครื่องตัวเอง
printf 'JWT_SECRET=%s\n' "$(openssl rand -hex 32)" > .env

docker compose up --build
```

ข้ามขั้นสร้าง `.env` แล้ว backend จะไม่ขึ้น และฟ้องในล็อกว่าให้กลับมาทำขั้นนี้
— ตั้งใจให้เป็นแบบนั้น ดีกว่าขึ้นมาแล้วใช้กุญแจที่ใครก็เดาได้
ดูรายชื่อค่าที่ต้องตั้งทั้งหมดได้ใน `.env.example`

เปิดใช้งานที่

| ปลายทาง | ที่อยู่ |
|---|---|
| หน้าเว็บ | http://localhost:3000 |
| เอกสาร API (Swagger UI) | http://localhost:8000/docs |

### บัญชีทดสอบ

ระบบสร้างให้เองตอนสตาร์ท ใช้ได้ทันทีหลัง `docker compose up`

| อีเมล | รหัสผ่าน | แพ็กเกจ | ไว้ทดสอบอะไร |
|---|---|---|---|
| `demo@example.com` | `password` | pro | ฟีเจอร์ที่ปลดล็อกเฉพาะแพ็กเกจ Pro |
| `admin@lebis-demo.com` | `admin1234` | admin | หน้าผู้ดูแลระบบ และ endpoint ที่กันด้วย `require_role("admin")` |

สมัครบัญชีใหม่เองที่ `/register` จะได้แพ็กเกจ `free` — ใช้คู่กับสองบัญชีข้างบน
เพื่อทดสอบว่าระบบล็อกฟีเจอร์ตามแพ็กเกจจริง

🔴 สองบัญชีนี้มีไว้สำหรับเครื่องตัวเองตอนพัฒนาเท่านั้น ตอนนำขึ้นใช้งานจริง
ต้องลบทิ้งหรือเปลี่ยนรหัสก่อนเสมอ

### หมายเหตุเรื่องพอร์ต Postgres

ในไฟล์ `docker-compose.yaml` ฐานข้อมูลถูก map ออกมาที่พอร์ต **5433** ของเครื่อง
(ไม่ใช่ 5432 ตามค่าปกติ) เพราะเครื่องคนทำมี Postgres ของโปรเจกต์อื่นจอง 5432 อยู่แล้ว

ต่อด้วยโปรแกรมจัดการฐานข้อมูล (DBeaver, TablePlus) ให้ใช้

```
host: localhost   port: 5433
user: temp        password: temp
database: advcompro
```

ส่วนข้างในเครือข่าย Docker บริการต่างๆ ยังคุยกันที่ `db:5432` เหมือนเดิม

ชื่อผู้ใช้กับรหัสของฐานข้อมูล (`temp` / `temp` ในไฟล์ `docker-compose.yaml`)
ใช้เฉพาะตอนรันบนเครื่องตัวเองเท่านั้น ฐานข้อมูลตัวนี้ไม่ได้เปิดออกสู่อินเทอร์เน็ต
ตอนนำขึ้นใช้งานจริง ค่าเชื่อมต่อฐานข้อมูลมาจาก Railway/Render โดยตรง
ไม่ได้ใช้ค่าที่เขียนไว้ในไฟล์นี้

### คำสั่งที่ใช้บ่อย

```bash
# ล้างฐานข้อมูลแล้วขึ้นใหม่ (ใช้เมื่อแก้ตารางใน setup_db())
docker compose down -v && docker compose up --build

# เข้า psql ใน container
docker compose exec db psql -U temp -d advcompro

# ดูรายชื่อตาราง
docker compose exec db psql -U temp -d advcompro -c "\dt"
```

## โครงสร้างโปรเจกต์

```
LEBIS-Project/
├── backend-api/          FastAPI
│   ├── app.py            จุดเริ่มต้นและการลงทะเบียน router
│   ├── database.py       การเชื่อมต่อ + setup_db() สร้าง 6 ตาราง
│   ├── routes/           ปลายทาง API ทั้งหมด (prefix /api)
│   ├── queries/          SQL ดิบ แยกตามโดเมน
│   ├── services/         JWT · LINE · ตัวแปลงข้อมูล
│   └── algorithms/       อัลกอริทึมเขียนมือ (วิชา Data Structures)
├── nextjs/               Next.js Pages Router
│   ├── pages/            1 หน้า 1 ไฟล์
│   └── components/ui/    shadcn-style components
├── docs/                 เอกสารส่งงาน
└── docker-compose.yaml   ขึ้นทั้งระบบด้วยคำสั่งเดียว
```

หน้าเว็บเรียก API ด้วย path แบบสัมพัทธ์ (`fetch("/api/items")`) แล้ว Next.js rewrite
ต่อไปที่ FastAPI ให้เอง — จึงไม่ต้องตั้ง CORS และไม่ต้องมี `NEXT_PUBLIC_API_URL`
